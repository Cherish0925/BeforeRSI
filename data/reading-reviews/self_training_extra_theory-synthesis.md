# 自训练组补读的理论、世界模型与工具智能体：16项比较结论

本文件对应 `self_training_extra_theory.jsonl` 的16项，均已读主文、实验、限制及相关技术附录。它们补足原87项自训练研究的环境、执行与评估条件。最终为11项support、5项mechanism_supplement，没有因数量配额升级核心。这里的“支持”指有明确解释作用，不意味着贡献小；“机制补充”也不等于已经实现改进算法自身的递归演化。

## 世界模型的三个不同问题

《General agents contain world models》回答的是一个必要性问题：在有限、完全可观测、平稳的communicating MDP上，如果策略对足够丰富的LTL目标都具有受限regret，就能通过构造目标并观察策略选择恢复环境动力学。证明不要求智能体内部存在一个显式的预测模块，也没有证明它在实际规划时调用这个模块。实验使用显式模型驱动的表格学习器，且最坏regret界在其样本范围中无实际约束力；平均表现与恢复误差的关系是有限的经验补充。该定理适合约束“通用能力意味着什么信息可被提取”的论证，不能用来宣布LLM已有可靠世界模拟器，更不能直接推出自改进闭环。

世界模型综述把隐式世界表征与未来预测两条研究线放在一起，适合定位概念与文献。二者是功能重心的不同，不应硬分成互斥架构。GAWM则实际训练RSSM世界模型和MAPPO策略：真实交互更新模型，模型生成想象轨迹供策略更新，下一批真实经验再回流。这是模型与经验分布互相影响的学习环，而其注意力结构、奖励平滑、缓冲区规则仍由作者固定。SMAC结果支持有限真实交互预算下的样本效率；没有同等总计算预算、完整世界模型成本或大规模训练模型证据，故列Model机制补充。

EvoWorld的“evolving”主要指视频生成过程中不断更新的显式3D点云记忆。视频模型离线微调，VGGT、检索和评判组件固定，部署时并不改模型或harness。这种几何状态能改善长期一致性，但相机轨迹、场景记忆和候选帧状态不能自动算作改进算法自身。其GPT-4o实验是四选一图像目标匹配，不能改写为真实导航成功；无世界模型的SVG提示还与正文的候选设置不一致。因此更可靠的比较是相同GenEx接口下加入EvoWorld后的变化，而不是把所有差值归因于世界建模。

## 外部状态什么时候算持续改进

MLC-Agent与ToolNet均有跨任务保留的外部状态，因而比普通任务内工具重试更接近Harness路线。MLC-Agent保留、共享、筛选骑手经验，改变后续提示上下文。实验中冻结的Qwen-Max条件与Q-learning、DAgger条件是不同对照，不能拼成“同时更新LLM权重和记忆”的Hybrid系统。其大规模城市送餐仿真提供一种记忆协作机制，但订单生成拟合用户评论时间，仍不足以验证真实配送世界的决策迁移。

ToolNet把工具调用轨迹形成的图与后续工具评分结合，历史反馈累计后改变下次工具选择。因此即使模型冻结，也存在持续外部策略更新。它仍不足以成为核心代表：静态图与动态反馈的独立效应未充分隔离，某些对照初始候选预算不等，若干任务低于对应强基线。它应作为判断边界的support节点——实际有跨任务反馈继承，但不能把所有增益都归给这一机制。

与之相比，Tool-Planner预先把相近功能API聚成簇，在当前任务出错时优先换同簇API，必要时再回退重规划。它有有效的局部修复结构，却没有跨任务继承的新规划器。Tool-to-Agent Retrieval则固定联合索引工具和agent，命中工具后映射到owner并去重，最终返回agent集合；它改进路由信息粒度，没有学习循环。MassTool离线训练图融合与分类头，BERT系编码器冻结，也未演示在线查询池扩展与真实工具执行反馈。三者都是执行或检索基础组件，不能因含图、聚类、记忆式索引或动态任务流程就称为Harness演化。

## 学习工具接口与学习工具使用策略

ToolGen将约47k API各编码成一个原子token，顺序进行文档记忆、查询检索、交互轨迹SFT。它统一了模型的动作表示，但并未让模型自己产生新训练任务，也没有在线更新工具目录。参数化工具知识的收益与代价同时可见：静态库检索强，未见指令端到端略有提高；未见工具的SoPR反低于同基座ToolLlama。所谓“未见工具”还只是后两个训练阶段缺少使用样本，阶段一已经见过全部文档。附录明确承认完全新增API仍需再训练。

ToolGen还有本组最清晰的遗忘对照之一：通用六任务均分从Llama-3的63.76降到26.94，混入50%通用指令后恢复到67.40，工具任务也进一步改善。它不是“工具学习必然扩大全域能力”的证据。Qwen2.5从7B扩大到14B也未提高端到端表现与未见工具迁移。最大实际训练14B，保留为动作接口与训练干扰的机制补充。

AutoTIR和DeepEyesV2进一步训练工具选择策略。AutoTIR用GRPO和任务—工具类型奖励鼓励数学用代码、知识题用搜索，故“自主”仍有明确人工先验。其一般指令遵循表现比只训某一工具的对照好，但IFEval仍从基座67.65降到51.02，不能称通用能力完全保留。DeepEyesV2主要依靠强教师轨迹冷启动，之后用答案正确性与格式奖励做DAPO；在其基座与数据设置中，直接RL会弃用工具，额外工具奖励又会诱发占位代码。这个失败与冷启动对照，比仅展示“出现复杂工具组合”更有解释力。

DeepEyesV2对新操作、函数调用有有限零样本迁移：TIR-Bench从基座16.0到RL后的20.8，新增旋转函数令特定OCR子集33.5到38.3。它没有达到普遍可靠工具迁移，迷宫案例也明确失败；训练源与评测均列V*而未披露该源隔离，需进一步污染审计。AutoTIR、DeepEyesV2实际学生都只有7B，Gemini、Claude或GPT的教师规模不进入训练规模统计。两者是Model机制补充，与ToolGen共同解释“接口可学习”“使用策略可学习”以及“学习后是否迁移”三个不同问题。

## 验证锚点：知道错在哪里与知道自己错了不同

《Helping LLMs Improve Code Generation Using Feedback from Testing and Static Analysis》在四个冻结模型上把功能测试、Infer报警、自评与逐轮修复分开测量。Llama3-70B是调用者而非被训练的学生。模型可能很差于自行诊断，却能根据外部失败测试修复代码；高度失衡的安全标签还能让几乎总答“无问题”的模型获得97–99% accuracy。支持自改进的验证器应看漏检、假阳性和目标覆盖，不能只报accuracy。

这篇研究的改善限于当前函数及三条已暴露测试、同一个静态分析器。报警消失不等于安全证明，功能修复与安全修复分开也不证明二者同时成立。主表92/155的修复数与引言96/155不一致，若干表行计数还少于分母，故保留其机制与失效模式，而不把精确百分比包装成已充分复现的通用结论。

CodeARC把从有限输入输出归纳隐藏程序的任务独立出来，提供已有代码题之外的验证角度。其数据生成教师能访问原始函数，学生并非凭自己能力无外部信息地产生正确课程。可见示例通过与oracle泛化差距很大，说明“通过本轮测试”不必意味着学到真实规则；其8B训练的归纳能力提升也没有同时带来普通知识式代码基准的提高。它适合与真实执行/隐藏测试锚点连线，而非归入强递归自训练。

Mind2Web提供2350个真实网页任务及跨任务、网站、领域划分，是后续web agent的有用训练和泛化基础。其原始评测每步输入人工真实历史，逐步独立预测，再计算所有步骤都命中的任务比例；这与在实时浏览器中经历自身错误并恢复不同。人工预先关闭弹窗和验证码，部分有副作用操作只作Click(Fake)记录，也限制了对真实部署的直接推论。MindAct的多选形式相较同模型直接生成有明显收益，但XL模型在跨网站、跨领域的全任务SR仍仅5.1%、2.9%。这些结果与可执行环境基准互补，提醒后续自改进论文同时报告局部预测能力和完整自主轨迹成功。

## 关系与取舍

本组支持一个一致的地图边界：训练后的权重、跨任务更新的外部决策状态、当前任务中的普通环境状态，应分开记录。世界状态不断增长，不等于世界模型继续学习；工具调用不断循环，不等于工具选择器被改进；高质量外部教师产生数据，也不等于学生自举出了监督信号。

显式方法继承只在原文有方法位置时标注：Tool-Planner对DFSDT的toolkit节点替换、ToolGen复用ToolBench与Agent-Flan式步骤分离、DeepEyesV2从DeepEyes管线扩展并采用DAPO。其他跨家族连线明确记为分析比较或互补，不把Related Work的引用自动升级为继承。最终16项全部保留可检索卡片，其中5项机制补充提供学习对象或反馈机制的实际证据，11项support补齐理论、环境、工具基础和评估限制；没有新增已确认≥27B学生训练节点。
