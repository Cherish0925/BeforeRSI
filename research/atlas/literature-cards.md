## EURISKO

1983 · Douglas B. Lenat · Stanford University · archive

[原文](https://www.cs.northwestern.edu/~mek802/papers/not-mine/Lenat_EURISKO.pdf) · 摘要、§1 表示与控制设计；历史溯源阅读。

**A · 目标与问题**
AM 可以发现领域概念，却难以发现有用的新启发式。EURISKO 要让程序同时改进“研究什么”和“怎样研究”。

**B · 关键思想**
关键不只是增加搜索次数，而是为启发式设计可操作的表示，使语法变异更可能产生有意义的规则。

**C · 系统与原理**
领域概念与启发式由带槽位的单元表示；条件、动作、用途和价值可被其他规则读取与修改。

**D · 算法与实现**
启发式提出任务与候选概念、修改规则并分配注意；系统依据已有结果更新优先级。

**E · 反馈与迭代**
新发现的规则可以参与后续发现，也可以作用于其他启发式；知识与控制规则因此相互影响。

**F · 结果与迁移**
论文讨论舰队设计、数学、程序与电路等八类任务。它是符号启发式发现的历史案例；依赖手工表示与人类参与，不能作为现代 LLM RSI 的规模证据。

## STOP

2023 · Microsoft Research / Stanford / OpenAI（研究在微软期间完成） · methods

[原文](https://arxiv.org/pdf/2310.02304) · arXiv:2310.02304v3（COLM 2024），§3–5，Algorithm 1，Figure 4，Table 1。

**A · 目标与价值**
优化的是生成更好程序的 improver，而不只是某一道题的解。它把自改进落实为一个可执行的元优化问题：后继程序能否更有效地改进下游解？

**B · 核心思想**
改进器也是程序，因此同一个代码改进接口可以作用于普通解，也可以作用于改进器自身。好坏由下游任务效用决定，而非让模型自行宣称改进成功。

**C · 结构与原理**
I(u,s,L) 用固定模型 L 改进解 s；meta-utility 是改进结果在任务集合上的平均效用。递归步骤为 Iₜ₊₁ = Iₜ(meta-utility, Iₜ, L)，可变对象是包含提示和搜索逻辑的 improver 源码。

**D · 算法与实验**
种子 improver 调用 LLM 生成多个候选，再执行效用函数选择候选。人类预设任务、评分函数、调用预算及递归轮数；实验主要用 GPT-4，并比较 GPT-3.5、Mixtral。

**E · 反馈与继承**
后继源码实际进入下一轮自修改，因而搜索策略可以被继承。作者观察到 beam search、遗传搜索等策略，但每轮性能并不保证单调增长。

**F · 成果与迁移**
作者报告 GPT-4 条件下的有限轮次收益，并把在 learning parity with noise 上产生的 improver 迁移到五类新任务。较弱模型实验反而退化，说明自应用接口本身不足以保证有效自改进。

**实验与资源：** 冻结 GPT-4-0314；另比较 GPT-3.5-turbo-0613、Mixtral-8x7B-Instruct-v0.1；调用次数、执行时间和递归轮数由实验协议限制。

## Promptbreeder

2023 · Google DeepMind · methods

[原文](https://arxiv.org/pdf/2309.16797) · arXiv:2309.16797v1，§3–6、Figure 1–2、Table 1；ICML 2024 论文页面核对出版信息。

**A · 目标与价值**
手写提示和固定改写指令可能限制提示搜索。Promptbreeder 研究能否把“怎样改写提示”也放进演化过程，让搜索适应具体任务领域。

**B · 核心思想**
把 task-prompt 和 mutation-prompt 组成同一个遗传单元。任务分数既选择解题提示，也间接选择与其绑定的变异策略，这是它的 self-referential 部分。

**C · 结构与原理**
普通变异生成 P′ = LLM(M + P)；hyper-mutation 再改写 M。模型权重、锦标赛选择代码、预设算子种类及评分协议保持固定；few-shot 版本还携带正确解题示例。

**D · 算法与实验**
二元锦标赛用较优个体的变体替换较差个体，结合直接变异、群体分布、hyper-mutation 等算子。论文使用 50 个体、通常 20–30 代，并在训练样本批次上估计适应度。

**E · 反馈与继承**
更新后的任务提示和关联变异提示进入后继种群，影响以后候选的产生。初始任务描述、thinking styles 和变异算子框架由研究者提供，不是所有搜索规则都自动演化。

**F · 成果与迁移**
作者在算术、常识推理和 ETHOS 分类上报告优于若干提示基线，并分析各变异组件的作用。主要证据是分领域提示演化；未展示一个通用提示改进器在开放任务流上持续自我增强。

**实验与资源：** PaLM 2-L 冻结；50 个体，通常 20–30 代；训练批次估计适应度，测试样本报告结果。

## Self-Rewarding LM

2024 · Meta / NYU · methods

[原文](https://arxiv.org/html/2401.10020v1) · arXiv v1（2024-01-18）；§2.1–2.4，§3.1.3，§3.2.1–3.2.2，Tables 1–2。

**A · 目标与价值**
固定 reward model 可能限制后续学习；论文探索奖励判断能否和指令跟随一起改善，实验基座是 Llama 2 70B。

**B · 核心思想与洞察**
把评审也写成指令跟随任务，使同一个模型既能回答，又能给回答评分；因此模型更新后，产生下一轮训练信号的能力也可能改变。

**C · 结构与原理**
先用人工种子做回答与评价 SFT，得到 M1；M1 生成并评分的偏好对用于 DPO 得到 M2，再重复得到 M3。

**D · 算法与实验**
每题采样四个回答，分别多次评分后选偏好对。新问题由固定 Llama 2-Chat 70B 生成，候选回答与评分使用当前迭代模型。

**E · 反馈与继承**
跨轮继承模型参数及生成偏好的能力；评价 rubric 和出题流程不随之演化。训练是分轮收集偏好后做 DPO，并非 PPO 式在线交互。

**F · 成果与迁移**
作者报告指令跟随与人类偏好一致性均改善；只加入高分回答做 SFT 未取得同样收益。回答长度随轮次增加，解释偏好胜率时也应考虑这一变化。

**实验与资源：** Llama 2 70B；两轮偏好集分别 3,964 / 6,942 对；256 题成对比较与 805 题 AlpacaEval 2。

## ADAS

2024 · UBC / Vector Institute · methods

[原文](https://arxiv.org/html/2408.08435v1) · arXiv:2408.08435v1，§2–3、§4.1–4.3、Figure 3、Table 1；Appendix A–B 的接口与提示。

**A · 目标与价值**
人工设计提示、反思和多 agent 协作只能覆盖少量组合。ADAS 把 agent architecture discovery 作为可搜索问题，研究能否自动找到更有效的控制流程。

**B · 核心思想**
用程序表达 agent，而非只在预列出的提示模板中选择。保留历史设计作为 stepping stones，使后来的候选可以重组早期发现，即使某个中间设计暂时分数不高。

**C · 结构与原理**
Meta Agent Search 的实际搜索对象是基础框架中的 forward 函数，框架提供模型查询和格式化接口。固定 meta-agent 编写目标 agent；二者未合并为同一个不断替换的改进器。

**D · 算法与实验**
meta-agent 根据档案提出设计，经新颖性/正确性反思和运行报错修订后，在验证集评测并入档。主实验由 GPT-4 设计、GPT-3.5 执行，按领域搜索 25 或 30 轮。

**E · 反馈与继承**
后续搜索读取候选源码、得分和置信区间；被继承的是设计经验与代码。评价函数、搜索外循环和 meta-agent 实现由研究者固定，目标 agent 的成功不会自动升级设计器。

**F · 成果与迁移**
作者在 ARC 子集、DROP、MGSM、MMLU、GPQA 报告收益，并将已发现设计迁移到未参与搜索的模型及任务。它提供自动 agent 设计与架构迁移的证据，而非完整的改进器递归替换实验。

**实验与资源：** 冻结 GPT-4 设计目标 agent，冻结 GPT-3.5 执行主实验；领域分别搜索；验证集用于发现，留出测试集用于报告。

## AFlow

2024 · DeepWisdom / HKUST / HKUST(GZ) / RUC / Nanjing / Fudan / KAUST / Montréal / Mila · methods

[原文](https://arxiv.org/html/2410.10762v4) · arXiv:2410.10762v4（ICLR 2025），§3.1–3.2、§4、Algorithm 1、§5.1–5.2、Table 1。

**A · 目标与价值**
自动工作流设计的瓶颈不仅是候选表达，还包括有限预算下怎样利用历史成功与失败。AFlow 针对这一搜索效率问题，把 workflow synthesis 组织为树搜索。

**B · 核心思想**
搜索树的一个节点代表完整 workflow；workflow 内部的节点才代表 LLM 调用，两者不能混淆。代码表达顺序、条件与循环，操作子提供已有的有效组合。

**C · 结构与原理**
实际搜索改变 prompts 和 code-represented edges，并组合 Generate、Review/Revise、Ensemble 等算子。模型、temperature、输出格式及外层 MCTS 变体固定，不进行模型训练。

**D · 算法与实验**
循环包含混合概率选父节点、LLM 扩展、验证集执行和经验回传；每个候选在验证集运行五次。人类提供算子、评分函数和预算，主实验搜索 20 轮，涵盖问答、数学和代码六个数据集。

**E · 反馈与继承**
保存相对父 workflow 的改动、效果及错误日志，下次扩展时复用这些经验。新 workflow 进入搜索树，但不替换搜索器代码；其能力积累发生在候选程序和搜索经验中。

**F · 成果与迁移**
作者报告在所划分测试集上，GPT-4o-mini 执行的六数据集平均指标为 80.3，对照 CoT-SC 为 76.0。论文也比较不同执行模型和成本；这些结果支持自动工作流搜索，不构成搜索器自身进化的证据。

**实验与资源：** Claude 3.5 Sonnet 作为 optimizer；GPT-4o-mini 等作为 executor；API 权重冻结；主搜索 20 轮，验证/测试按 1:4 划分。

## SICA

2025 · iGent AI / University of Bristol · methods

[原文](https://arxiv.org/html/2504.15228v1) · arXiv:2504.15228v1，§3、Algorithm 1、§4、Table 1、§4.1。

**A · 目标与价值**
研究具有文件、终端和子 agent 能力的编码系统，能否自行改进工具与执行方式。目标同时包含完成任务的能力、运行时间和费用。

**B · 核心思想**
target-agent 与 meta-agent 共享同一可编辑实现：执行任务的版本也负责产生后继版本。与固定设计器生成目标 agent 相比，改进后的工具能力可以参与下一轮自修改。

**C · 结构与原理**
可编辑对象包括 agent 源码、工具、提示、子 agent 和上下文组织；主实验使用冻结的 Sonnet 3.5 与 o3-mini。外层档案选择、任务集合及效用定义由研究者给定。

**D · 算法与实验**
每轮运行基准任务、记录准确率和成本，再让历史效用最好的 agent 阅读档案并实现一个新版本。编码实验包含固定随机抽取的 50 道 SWE-bench Verified、50 道 LiveCodeBench 及文件编辑和符号定位任务。

**E · 反馈与继承**
候选版本及分数存入档案，被选中的版本成为后续修改者。轨迹中出现 diff/range 编辑器和 AST 符号定位器，具体工具改变成为可复用的系统资产。

**F · 成果与迁移**
作者报告 SWE-bench 子集成绩从 17% 提升至最高 53%；这不是完整 500 题的成绩。推理任务上的收益明显较弱，说明 harness 改进取决于任务瓶颈和基座模型能力。

**实验与资源：** 冻结 Sonnet 3.5 v2；推理子 agent 使用 o3-mini；评分含准确率、时间和美元成本；主编码实验反复使用固定任务子集。

## DGM

2025 · Sakana AI / UBC / Vector Institute · methods

[原文](https://arxiv.org/html/2505.22954v3) · arXiv v3（2026-03-12）；§3，§4.1–4.4。

**A · 目标与价值**
目标是自动改进 coding agent 的工具与执行流程，并让这些改动继续参与后续开发；实验对象是冻结 LLM 驱动的可编辑 Python 程序。

**B · 核心思想与洞察**
只沿当前最优版本前进，可能丢掉有用的中间结构。DGM 保留仍能编辑代码的历史分支，使暂时降分的版本也能成为后续改进的起点。

**C · 结构与原理**
父代既执行编码任务，也修改自己的代码；archive 保存程序谱系与评测结果。父代选择倾向高分、后代较少的分支，档案维护与选择规则由外层固定。

**D · 算法与实验**
每轮根据运行日志提出改动，实施代码修改，再分阶段评测新 agent。论文运行 80 轮，并对比固定改进者、取消历史档案两种设置。

**E · 反馈与继承**
继承的是可运行代码、工具和工作流，而不是新的 LLM 权重。后继再用这些能力改写自身，因此反馈路径经过真实的软件执行与版本继承。

**F · 成果与迁移**
作者报告 SWE-bench 评测子集从 20% 到 50%，全量 Polyglot 从 14.2% 到 30.7%；还测试了跨模型迁移。这支持代码层自改进及分支探索的效果，不能把子集成绩当作全量成绩。

**实验与资源：** 冻结基础模型；80 次进化；SWE-bench 与 Polyglot，采用分阶段任务子集评价。

## GEPA

2025 · UC Berkeley / Stanford / Notre Dame / MIT / Databricks / Bespoke Labs · methods

[原文](https://arxiv.org/pdf/2507.19457v2) · arXiv 2507.19457v2 PDF；§3、§3.1、Figure 3、Algorithms 1–2、§4。

**A · 目标与价值**
复杂 agent 的一次执行会产生推理、工具调用和错误信息。GEPA 要将这些信息用于提示优化，减少只凭最终分数反复试错的成本。

**B · 核心思想与洞察**
执行轨迹能说明错误发生在哪里；不同提示又可能擅长不同样本。反思负责提出有针对性的改动，Pareto selection 负责保留互补策略。

## MASS

**B · 核心思想与洞察**

## ACE

[原文](https://arxiv.org/html/2510.04618v1) · arXiv:2510.04618v1，§2.2、§3.1–3.2、§4.1–4.3、Table 1；§4.5–4.6 的组件和成本分析。

**实验与资源：** 三个角色均用冻结 DeepSeek-V3.1 non-thinking；离线最多 5 epochs、Reflector 最多 5 轮；AppWorld 使用官方 ReAct 框架。

## On-policy Co-evolution

2026 · Salesforce AI · methods

[原文](https://arxiv.org/html/2609.09134v1) · arXiv v1（2026-09-08）；§3.1–3.4，Tables 1–3；Appendix B–C。

**A · 目标与价值**
Harness 与模型权重都会改变 agent 行为；问题是先优化 Harness 后，怎样继续训练模型，使两种改进能够组合。

**B · 核心思想与洞察**

**C · 结构与原理**
先用学生运行任务，并以 GEPA-style search 修改提示、工具、hooks 和上下文；随后保留学生失败轨迹的周围步骤，只让教师改写定位出的失败回合。

**D · 算法与实验**
局部纠正数据混合学生自身成功轨迹，再做 LoRA-SFT，并在同一演化 Harness 中复测。这里 on-policy 指数据来自学生访问的状态，参数训练目标仍是监督学习。

**E · 反馈与继承**
保留优化后的 Harness 与更新的学生权重；下一轮可以再围绕新学生优化 Harness。主要结果检验一次 Harness 演化后的模型适配，反复多轮属于提出的接续流程。

**F · 成果与迁移**
Qwen3-Coder-30B-A3B 的七任务平均成功率：演化 Harness 为 78.0%，整轨迹模仿为 63.1%，局部纠正为 79.7%。这一结果支持适配方式的重要性，规划失配是作者据失败分析提出的解释。

**实验与资源：** 主实验 Qwen3-Coder-30B-A3B（总 30B / 激活 3B），LoRA SFT；Gemma-4-26B-A4B 为 <27B 补充实验，7 个企业任务。

预设工具未必适合每个仓库和 issue，复杂 bash 命令也可能增加上下文与操作错误。该工作研究 task-time tool synthesis，按当前问题构造更合适的搜索、编辑和分析工具。

**B · 核心思想**
工具本身也是可执行代码，agent 可以在发现具体需要后再编写和使用。工具选择因此从固定工具箱扩展为随任务产生的程序，而不必事先穷举全部工具。

**C · 结构与原理**
论文 §2.1 明确说明不改变 agentic loop；修改是在初始提示和每步环境反馈后加入反思提示。custom tool 被定义为环境中可执行的 script，基础模型及 agent 外循环固定。

**D · 算法与实验**
agent 根据刚发生的操作结果决定是否写脚本，随后通过 shell 执行并可继续修订。实现基于 mini-SWE-agent，默认每题最多 250 步、3 美元；实验覆盖 SWE-bench Verified 和 SWE-Bench Pro。

**E · 反馈与继承**
脚本执行输出和 issue 的测试反馈影响当前任务中的后续工具设计。论文展示同一任务内的创建、使用与修订，没有建立跨 issue 持久工具库或代际改进器替换实验。

**F · 成果与迁移**
v1 作者报告 Claude 4.5 Sonnet 在完整 SWE-bench Verified 上由 mini-SWE-agent 的 70.6% 提升至 75.4%，在 SWE-Bench Pro 为 45.8%。这是在线工具合成的任务收益，不能表述为已改写整个 agent 框架。

**实验与资源：** 冻结 Claude 4.5 Sonnet 为默认基座；另测试 GPT-5/GPT-5-Mini；temperature 0、250 steps、每题 3 美元上限、每题单补丁。

## DeepSeekMath-V2

2025 · DeepSeek-AI · methods

[原文](https://arxiv.org/html/2511.22570v1) · arXiv v1（2025-11-27）；§2.1–2.3，§3.1–3.3；特别是 Eqs. 3、5–6。

**A · 目标与价值**
证明题不能只检查最终答案；正确答案也可能伴随错误推导。论文目标是训练能发现具体逻辑问题、并帮助生成器修正证明的验证能力。

**B · 核心思想与洞察**
只奖励评分正确，会出现“分数对、理由错”的 verifier。Meta-verification 进一步检查所指出的错误是否真实存在、是否足以支持评分。

**C · 结构与原理**
系统包含证明生成、证明验证和验证意见复核。生成器同时输出证明与自评，奖励既看证明质量，也看自评是否诚实、理由是否成立。

**D · 算法与实验**
用 GRPO 先训 verifier，再从其 checkpoint 训练 generator；后续轮次先通过 rejection fine-tuning 汇合两种能力。新证明经多次验证及元验证筛选，形成下一轮训练标签。

**E · 反馈与继承**
更强 generator 提供更难判断的证明，更强 verifier 再指导生成；末两轮采用自动标注替代人工标注。持久更新发生在模型参数，评分规则仍由研究者给定。

**F · 成果与迁移**
作者在竞赛证明任务上报告明显进展，并用推理时迭代提高证明质量。高计算量搜索成绩与单次生成成绩分别报告；自然语言 verifier 的认可仍不同于形式证明器的验证。

**实验与资源：** DeepSeek-V3.2-Exp-Base 的 671B 级模型；公开配置仅路由专家矩阵已超过 653.9B。

**A · 目标与价值**
创作、解释和复杂问答通常没有可直接执行的正确答案判定器。K2 要将强化学习从可验证任务扩展到这些开放任务。

**B · 核心思想与洞察**
奖励评价也会遇到新策略产生的新行为。论文用 on-policy 的可验证轨迹持续校准 critic，让其判断不完全停留在初始偏好数据上。

**C · 结构与原理**
K2 actor 生成回答，K2 critic 按 core、prescriptive 及人工任务 rubric 做成对比较；critic 先经偏好数据 SFT，再接受可验证信号更新。

**D · 算法与实验**
actor 使用 K1.5 系列的策略优化目标；同题采样回答，以组内相对奖励驱动参数更新。可验证任务的 rollout 同时为 critic refinement 提供数据。

**E · 反馈与继承**
形成 actor → 当前轨迹 → critic 更新 → actor 奖励的反馈回路。演化对象是模型参数；人工 rubric 与训练基础设施没有在该闭环中自主改写。

**F · 成果与迁移**
技术报告展示了这一机制如何进入大规模 K2 后训练，并报告最终模型的广域表现；公开结果没有把该闭环的独立贡献从整套训练流程中完全分离。

**实验与资源：** 约 1.04T 总参数、32B 激活；本条讨论后训练自评价机制。

## LLMs Can Self-Improve

2022 · Google / UIUC · methods

[原文](https://aclanthology.org/2023.emnlp-main.67.pdf) · EMNLP 2023 正式版：§3–5、Figure 1、Tables 3–6

**A · 目标与价值**
标准答案与人工推理示范难以持续扩充；本文研究仅有问题时能否获得有效训练信号。

**B · 思想与洞察**
利用 self-consistency 聚合多条推理路径，把推理时多次采样的收益部分转入参数。

**C · 结构与原理**
多数答案作为伪标签，只保留支持该答案的推理链；一致性提供选择依据，但不等同于正确性证明。

**D · 算法与实验**
离线生成数据，以多种提示格式组织样本，再对同一 PaLM 540B 做监督微调；论文还测试自生成问题。

**E · 反馈与演化**
自身输出经筛选回到参数更新；主要实验是一轮 self-training，没有展示持续多代能力增长。

**F · 成果与迁移**
作者报告 GSM8K 的 CoT 准确率从 56.5% 升至 73.5%，并在未参与训练的任务上测试迁移。关键变量是伪标签质量与推理多样性。

**实验与资源：** PaLM 540B；2022 预印本、2023 正式发表。

## OPHIS

2026 · MetaCircle · methods

[原文](https://meta-circle.com/blog/ophis-a-new-paradigm-for-autoresearch) · 官方博客：OPHIS framework；Grokking / NanoGPT 两个案例；Looking Forward

**A · 目标与问题**
让自动研究从可观测的训练动力学出发，找到可解释、可干预的学习瓶颈。

**B · 关键思想**
把“哪次实验分数更高”推进为“内部哪些量发生变化，为什么值得干预”。这是一条观测驱动的 AI4AI 路线。

**C · 系统与原理**
Observation → Problem → Hypothesis → Intervention → Speed-up。博客称核心方法非 LLM；NanoGPT 案例又明确采用 coding agent，二者应按实验分别理解。

**D · 算法与实现**
测量张量统计量并提出干预。NanoGPT 设置固定为 2,000 步、单 H200，每个候选重复评估十次；部分内部规则未公开。

**E · 反馈与迭代**
成功干预引导相邻观测量探索，也选择不同方向。公开材料未展示研究代理参数的在线更新或后继接管改进器。

**F · 结果与边界**
作者报告 NanoGPT 平均 BPB 从 0.9340967 到 0.9318420。任务小、预算协议不同，不能直接把差值当作优于另一公司的通用能力结论。

**实验与资源：** Grokking 与 NanoGPT；单 H200；2,000 训练步；每候选十次评估。
