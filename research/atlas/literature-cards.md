# RSI 公开研究阅读档案

方法卡片、摘要档案与历史阅读分开标明。A–F 是阅读角度；没有材料支持的部分不填充套话。

## Good：智能机器设计

1965 · 署名机构尚未整理 · archive

[原文](https://doi.org/10.1016/S0065-2458(08)60418-0) · 摘要与既有来源记录

**A · 目标与问题**
智能机器能否设计更强机器，从而加快后续设计？

**C · 系统与原理**
Good 提出能力提升与机器设计能力之间的正反馈设想。

**F · 结果与迁移**
这是思想性论证，没有给出可执行的训练算法或实证增长曲线。

## EURISKO

1983 · Douglas B. Lenat · Stanford University · archive

[原文](https://www.cs.northwestern.edu/~mek802/papers/not-mine/Lenat_EURISKO.pdf) · 摘要、§1 表示与控制设计；历史溯源阅读。

**A · 目标与问题**
AM 可以发现领域概念，却难以发现有用的新启发式。EURISKO 要让程序同时改进“研究什么”和“怎样研究”。

**B · 关键思想**
关键不只是增加搜索次数，而是为启发式设计可操作的表示，使语法变异更可能产生有意义的规则。

**C · 系统与原理**
领域概念与启发式由带槽位的单元表示；条件、动作、用途和价值可被其他规则读取与修改。

**D · 算法与实现**
启发式提出任务与候选概念、修改规则并分配注意；系统依据已有结果更新优先级。

**E · 反馈与迭代**
新发现的规则可以参与后续发现，也可以作用于其他启发式；知识与控制规则因此相互影响。

**F · 结果与迁移**
论文讨论舰队设计、数学、程序与电路等八类任务。它是符号启发式发现的历史案例；依赖手工表示与人类参与，不能作为现代 LLM RSI 的规模证据。

## STOP

2023 · Microsoft Research / Stanford / OpenAI（研究在微软期间完成） · methods

[原文](https://arxiv.org/pdf/2310.02304v3) · 首页署名与脚注；§3–4、Algorithm 1、迁移实验

**A · 目标与问题**
能否让程序改进器改写自身，使它以后生成更好的程序？

**B · 关键思想**
把“更好的解”推进到“更好的产生改进的程序”。

**C · 系统与原理**
用调用冻结 GPT-4 的改进程序修改该改进程序自身。

**D · 算法与实现**
从生成并选择候选程序的种子改进器开始，把改进器源码本身作为待优化程序；下游程序的效用用于评价改进器。

**E · 反馈与迭代**
改进程序产生后继；后继继续生成程序改进。

**F · 结果与迁移**
作者报告后继改进程序在受限算法任务上优于种子，包含跨任务检验。
任务规模有限；作者也未称为全部组件均可改的完整 RSI。

**实验与资源：** GPT-4 冻结；改进器代码可变；算法任务与规定调用预算。

## Promptbreeder

2023 · Google DeepMind · methods

[原文](https://arxiv.org/pdf/2309.16797v1) · 首页；§3、§4、Table 1；ICML 2024 正式版另列

**A · 目标与问题**
能否同时优化任务提示和产生提示变异的方法？

**B · 关键思想**
明确让变异机制成为可继承的搜索对象。

**C · 系统与原理**
共同演化任务提示与生成变异的提示，基础模型冻结。

**D · 算法与实现**
维护任务提示与变异提示的种群，用模型执行提示变异和任务测试；变异提示本身也参与演化。

**E · 反馈与迭代**
任务提示与对应变异提示共同进入后继种群。

**F · 结果与迁移**
在算术、常识和分类任务上报告提示搜索收益，并分析自指成分。
提示演化不等于模型训练，也不证明开放任务上的持续加速。

**实验与资源：** PaLM 2-L 冻结；多代种群；训练样本作适应度、测试集报告结果。

## Self-Rewarding LM

2024 · Meta / NYU · methods

[原文](https://arxiv.org/html/2401.10020v1) · §2.1–2.4，§3.1–3.2；特别是 §3.1.3 的固定出题模型。

**A · 目标与问题**
模型能否同时生成回答和偏好评价，并据此训练下一代？

**B · 关键思想**
把回答者与奖励者放进同一参数继承链；主要贡献在学习信号及其迭代，而非修改 agent 软件。

**C · 系统与原理**
同一 70B 模型产生回答并评分；每轮构造偏好对，以 DPO 更新下一代，再由下一代生成回答与偏好。

**D · 算法与实现**
后训练；种子 SFT → 迭代 DPO；轮间在线生成偏好；每轮 DPO 优化已收集的偏好对，不等于 PPO 在线 RL。

**E · 反馈与迭代**
M1 生成回答与偏好训练 M2；M2 再生成偏好训练 M3；出题模型固定。

**F · 结果与迁移**
核对 §2–3：M1 为种子 SFT，M2/M3 为两次 DPO；另评指令跟随与奖励排序，并比较仅正例 SFT。
实际新题由固定 Llama 2-Chat 70B 生成；有人类种子、外部评审和早停。不证明无外部信息或无限递归增长。

**实验与资源：** Llama 2 70B；两轮偏好集分别 3,964 / 6,942 对；256 题成对比较与 805 题 AlpacaEval 2。

## ADAS

2024 · UBC / Vector Institute · methods

[原文](https://arxiv.org/html/2408.08435v1) · 首页；§3、§4.3、Appendix G

**A · 目标与问题**
能否自动发现代理的控制流程，而不只调一个提示词？

**B · 关键思想**
把完整控制流的自动设计与跨域、跨模型迁移连接起来。

**C · 系统与原理**
固定 meta-agent 依据档案编写、评测目标 agent 的 forward 实现。

**D · 算法与实现**
Meta Agent Search 读取已有设计档案，生成目标代理的 forward 代码，通过执行反馈修订候选。

**E · 反馈与迭代**
设计结果写回档案；改进器从档案学习上下文，但其实现固定。

**F · 结果与迁移**
报告 ARC、推理任务和跨域/跨模型迁移；有成本附录。
自动设计前身；生成的目标 agent 没有替换固定 meta-agent。

**实验与资源：** 冻结基础模型；meta-agent 与目标 agent 分离。

## SICA

2025 · iGent AI / University of Bristol · methods

[原文](https://arxiv.org/html/2504.15228v1) · 首页；§3、Algorithm 1；§4 与 Appendix D

**A · 目标与问题**
编码代理能否修改自己的实现，并把改进后的版本用于下一轮自修改？

**B · 关键思想**
执行者与改进者共享可编辑实现；成本和速度也进入选择。

**C · 系统与原理**
从历史档案选当前最佳 agent，让它修改自己的代码库。

**D · 算法与实现**
从历史版本中选择代理，修改代码并在规定任务上执行；选择效用同时考虑成功率、时间与费用。

**E · 反馈与迭代**
被选中的后继 agent 承担下一轮自修改。

**F · 结果与迁移**
作者在 SWE-bench Verified 随机子集报告 17%→53%，并报告其他编码/推理任务结果。
不能把子集分数说成完整 SWE-bench 成绩；未证明后继改进效率持续增长。

**实验与资源：** 冻结 LLM；SWE 子集、LiveCodeBench 与合成任务；选择效用含时间和费用。

## DGM

2025 · Sakana AI / UBC / Vector Institute · methods

[原文](https://arxiv.org/html/2505.22954v3) · §3–4，尤其 §4.2–4.4 与谱系图

**A · 目标与问题**
怎样保留暂时不占优、却可能产生更强后代的代理分支？

**B · 关键思想**
可运行的自修改与开放谱系结合；较差的中间节点仍可能成为有价值的祖先。

**C · 系统与原理**
智能体修改自身代码，保留多个历史分支，再由选中的后继继续修改。

**D · 算法与实现**
从代理档案采样父代，执行代码自修改，用分阶段编码任务评价新版本，并把后继加入档案继续分支搜索。

**E · 反馈与迭代**
保留候选代理并用于后续代码改进；不等于已证明改进速度持续增长

**F · 结果与迁移**
比较固定改进者、去掉谱系档案等设置，并报告跨模型与编码任务迁移。
开放搜索的收益仍受评估次数、选择集和基座能力影响；未证明无限增长。

**实验与资源：** 冻结基础模型；80 次进化；SWE-bench 与 Polyglot，采用分阶段任务子集评价。

## GEPA

2025 · UC Berkeley / Stanford / Notre Dame / MIT / Databricks / Bespoke Labs · methods

[原文](https://arxiv.org/pdf/2507.19457v2) · 首页；§2–4、Algorithm 1、实验与成本设置

**A · 目标与问题**
怎样利用执行轨迹中的语言反馈，更高效地搜索提示与程序配置？

**B · 关键思想**
以语言反馈改善搜索样本效率，是 harness 优化的重要比较基线。

**C · 系统与原理**
反思执行轨迹、修改提示，并从 Pareto 前沿组合互补候选。

**D · 算法与实现**
收集执行轨迹，反思具体失败并提出提示修改；维护 Pareto 候选，组合互补改动。

**E · 反馈与迭代**
候选提示及轨迹反馈进入后续搜索；外层优化算法固定。

**F · 结果与迁移**
六任务报告与 GRPO、MIPROv2 的比较；需要同时看反思模型成本。
优化器本身未证自改；较少 rollout 不等于同比总 FLOPs 或费用。

**实验与资源：** 提示优化基座冻结；GRPO 是对照，不应把其训练算成 GEPA 的参数更新。

## SEAL

2025 · MIT · Improbable AI Lab / CSAIL · methods

[原文](https://arxiv.org/html/2506.10943v1) · §3；§4 few-shot setup；Appendix A

**A · 目标与问题**
怎样让模型学会生成真正有利于自己学习的数据和更新指令？

**B · 关键思想**
评价对象从答案质量转为“这项自编辑使当前学习者怎样改变”。

**C · 系统与原理**
模型产生训练数据或更新配置，执行内层学习后，用学习者的效果训练生成策略。

**D · 算法与实现**
后训练 / 测试时适应；ReST-EM 外层 + 内层微调；当前策略采编辑，执行内层学习后构造反馈。

**E · 反馈与迭代**
按内部微调后的效果更新编辑策略；受训练设置约束。

**F · 结果与迁移**
比较未训练的自编辑和学习后的自编辑；奖励随学习者变化，文中采用 on-policy 更新。
小规模且筛选的 ARC 结果不能外推一般智能；旧编辑奖励对新学习者可能失效。

**实验与资源：** 知识吸收为 Qwen2.5-7B；ARC 为 Llama-3.2-1B，筛选后 11 个训练 / 8 个评测任务。

## HyperAgents

2026 · Meta / UBC / Vector / Edinburgh / NYU · methods

[原文](https://arxiv.org/html/2603.19461v1) · §3–5；§4.1 对照；Appendix D / E 元层变化

**A · 目标与问题**
如果任务能力不等于修改能力，能否直接让元代理的改进过程也可编辑？

**B · 关键思想**
相对固定修改提示，把生成改进的方法开放给经验选择。

**C · 系统与原理**
任务代理和修改代理位于同一可编辑程序，元层诊断与修改流程也能被改写。

**D · 算法与实现**
把 task agent 与 meta-agent 合为同一可编辑程序，在 DGM 的档案与分支搜索上开放整个元修改机制。

**E · 反馈与迭代**
后继的可编辑元代理继续提出改动；主要父节点选择仍由外层设定

**F · 结果与迁移**
包含冻结元代理、去掉档案等对照，以及跨域元层迁移；主实验父代选择仍固定。
可表达任意程序不等于能有效发现任意改进；不同领域评价可信度不同。

**实验与资源：** 编码、论文评审、机器人奖励设计、数学评分；冻结基础模型，多域代理实验。

## Updating ≠ Benefit

2026 · Amazon / Penn State / UCSC / Emory / UIUC / Northeastern · methods

[原文](https://arxiv.org/html/2605.30621v1) · §3.2–3.3、§4；Appendix B–D

**A · 目标与问题**
擅长改 harness 的模型，与能从改动中获益的模型，是同一种能力吗？

**B · 关键思想**
提出可测的能力分解，反驳“模型越强，必然越会改且越受益”。

**C · 系统与原理**
固定执行者更换改进者，再固定改进者更换执行者，分离两种能力。

**D · 算法与实现**
交叉替换 evolver 与 executor，把产生改动的能力和利用改动的收益分开测量。

**E · 反馈与迭代**
检验闭环、收益与成本，不以评测论文冒充新的 RSI 系统。

**F · 结果与迁移**
原文报告更新收益与基础能力关系较平、使用收益随执行者明显变化。
在线累计收益不能替代冻结后继的未来任务评价；相关模式未证明普遍因果律。

## Iterative RPO

2024 · Meta FAIR / NYU · methods

[原文](https://arxiv.org/html/2404.19733v2) · 首页；§2、§3.1–3.3、Appendix A

**A · 目标与问题**
为什么直接用 DPO 学推理可能不稳定，怎样有效使用自生成的正负推理链？

**B · 关键思想**
正例似然项与偏好项结合；解释直接套 DPO 对推理不稳定的问题。

**C · 系统与原理**
用当前模型生成推理候选，按答案正确性组成偏好对，再用 DPO+NLL 更新。

**D · 算法与实现**
后训练；迭代 DPO + 正例 NLL；每轮重新采样；轮内偏好数据固定；不是 PPO。

**E · 反馈与迭代**
新权重生成下一轮偏好对，并作为下一轮参数与参考模型。

**F · 结果与迁移**
70B 多轮训练改善三个推理任务，包含 DPO/NLL 消融；收益最终饱和。
依赖外部正确答案；没有学习训练算法或证明通用自主科研能力。

**实验与资源：** Llama-2-70B-Chat；GSM8K、MATH、ARC-Challenge；固定训练问题和答案。

## DeepSeekMath-V2

2025 · DeepSeek-AI · methods

[原文](https://arxiv.org/html/2511.22570v1) · §2.1–2.3、§3.1–3.3；官方 Math-V2 config.json 与 V3.2-Exp 部署配置

**A · 目标与问题**
复杂数学证明没有简单答案校验时，怎样扩展可靠的训练反馈？

**B · 关键思想**
反馈能力也随生成能力更新；不只奖励最终数值答案。

**C · 系统与原理**
迭代训练证明验证器与生成器，并用元验证筛选自动标注。

**D · 算法与实现**
后训练；GRPO + 轮间 rejection fine-tuning；每轮生成器从验证器初始化；次轮验证器继承融合后的前轮能力。

**E · 反馈与迭代**
生成器产生更难证明→验证/元验证标注→更新验证器→再训练生成器。

**F · 结果与迁移**
最后两轮由自动标注取代人工标注；报告数学证明表现及专家评估。
非形式化验证仍可能犯错；高计算搜索成绩不是单次生成分数，亦未证明全域递归加速。

**实验与资源：** DeepSeek-V3.2-Exp-Base 的 671B 级模型；公开配置仅路由专家矩阵已超过 653.9B。

## Kimi K2

2025 · Moonshot AI（月之暗面） · methods

[原文](https://arxiv.org/html/2507.20534v1) · §1、§3.2.2–3.2.3、§4 与 Appendix F

**A · 目标与问题**
开放式任务难以自动判分，怎样让奖励评价跟上正在更新的策略？

**B · 关键思想**
把可验证任务的反馈迁入开放任务评价，并避免评价器完全冻结。

**C · 系统与原理**
K2 actor 生成回答，K2 critic 按 rubric 提供偏好，critic 又从可验证的 on-policy 轨迹更新。

**D · 算法与实现**
后训练；策略 RL + critic 在线校准；可验证 on-policy 轨迹训练 critic；critic 为开放任务提供偏好。

**E · 反馈与迭代**
当前策略轨迹更新 critic；critic 的反馈继续训练策略。

**F · 结果与迁移**
技术报告明确描述策略—critic 闭环；最终模型有广域评测。
报告未充分隔离该闭环对最终总成绩的因果贡献；人工 rubric 仍是锚点。

**实验与资源：** 约 1.04T 总参数、32B 激活；本条讨论后训练自评价机制。

## LLMs Can Self-Improve
