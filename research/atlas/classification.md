# 三层入口之下：对象、机制、闭环与证据

2026-10-18。本文件是本项目的分析约定，不是引用某篇论文的统一定理。它解释如何保持入口简洁，同时避免把不同问题混成一个分类。

## 1. 三条主线为什么成立，边界在哪里

先声明研究的系统边界、比较的两个版本，以及观察的时间尺度。

- **M：参数化模型。** 包括执行者、评价者、奖励模型、世界模型、出题者、训练决策模型，以及它们的权重、adapter 和模型自身结构。模型结构变化和 agent 组织结构变化分开记录。
- **H：边界内的外部机制与持久状态。** 包括运行和训练软件、控制与工具、外部记忆和知识库、环境与资源调度。只有系统实际能修改、保留并复用的部分，才记为自改对象。
- 外部世界、人类给定目标和独立审计条件单列。不能把所有不可控制的外界都塞入 H，也不能把每次普通任务输出算作系统改进。

令 m/h 表示两版本间 M/H 是否存在实质且被继承的改变。排除两者均不变后，(m,h) 只有 (0,1)、(1,0)、(1,1)，分别对应 Harness、Model、混合。这是**相对于已声明边界的对象划分完备性**，不证明领域调研已完备，也不证明更新有益、已经递归或具有统一增长规律。

三个入口不是高低层级。参数化评价器属于 M，评价代码属于 H；多个模型共同训练仍可只属于 M。普通训练也改变 M，因此“落在 Model 桶”不是 RSI 资格证。

## 2. Harness 按功能拆分，文件类型只是载体

| 功能 | 具体可改对象 | 不能混淆的事情 |
|---|---|---|
| 信息与持久记忆 | 提示、上下文管理、经验、知识库、数据库、检索/淘汰策略 | 写入答案与改善获取、组织、使用知识的方法不同 |
| 工具与行动接口 | 工具代码、插件、skills、MCP 接口、操作协议 | 调用既有工具与改进工具不同 |
| 组织、控制与搜索 | 规划、路由、分工、多智能体通信、搜索及谱系 | agent 数量增加不自动提高协同或改进能力 |
| 学习与研发流程 | 训练程序、损失、优化器代码、数据筛选、实验与算力分配 | 训练器改了与它训练的模型改了分别记录 |
| 评价、选择与继承 | 测评、验证器、奖励代码、晋升、剪枝、回退、档案 | 优化评分程序不等于提高真实能力；固定外部锚点另列 |
| 执行、环境与资源 | runtime、沙箱、可控环境、编译、服务、调度与 infra | 固定预算下效率改善与增加预算不同 |

这六类是功能视图，允许一项修改涉及多类。一个数据库既可以储存知识，也可以记录实验谱系；分类根据实际用途，而非文件后缀。训练语料 D 仍保留原仓库的来源/版本记录：临时生成训练样本不自动算 H 自改；如果形成持续被修改和使用的知识资产、数据选择器或课程机制，才另外记录 H 路径。

## 3. Model 不能用一串互斥技术名称来分

一项实验用六个相互独立的字段描述；同一工作只填已经核准的内容。

| 维度 | 需要回答的问题 | 可取值示例 |
|---|---|---|
| 被训练角色 | 谁的参数实际变化？ | 执行者、评价/奖励者、出题者、世界模型、改进者 |
| 学习阶段 | 处于模型生命周期哪一步？ | 从零预训练、继续预训练、后训练、测试时/持续适应 |
| 学习目标 | 学习什么信号？ | 自监督、监督似然、偏好、可验证奖励、过程反馈、学习增益 |
| 更新算法 | 怎样改变参数？ | 全参/adapter SFT、DPO、PPO/GRPO、蒸馏、元学习、结构搜索 |
| 数据与时间 | 数据何时产生，是否依赖当前策略？ | 固定离线集、按轮刷新、on-policy 轨迹、回放、异步在线交互 |
| 继承与回流 | 谁进入下一轮，怎样进入？ | 接续参数、每轮重置学生但继承教师、群体、更新后继续产生数据/奖励/改进 |

**on-policy ≠ RL；在线生成数据 ≠ 在线梯度更新；后训练 ≠ RSI；训练多个模型 ≠ Model × Harness。** 例如 Self-Taught Evaluators 的下一轮学生从同一初始种子重训，回流经由上轮评价器生成的监督；Self-Rewarding LM 则接续参数做迭代 DPO。两者都不应写成同一种“在线自训练”。

## 4. 混合路线要拆开“并存、作用、闭环、收益”

1. **并存/联合工程**：同时有强模型和强 harness，但没有双方自主更新证据。列 AI4AI 支撑，不算已证共演。
2. **单向作用**：H 的轨迹/工具/课程进入 M；或 M 的变化触发 H 调整。记录箭头方向。
3. **序列联合适配**：两者均更新，已测联合效果；若只展示一次 H→M，不写成持续互相回流。
4. **闭环共演**：M 更新后确实再次参与 H 改进，H 反馈又影响 M。记录代数、更新顺序与人的参与。
5. **协同收益**：即便存在闭环，也须测是否优于单独更新、是否保持泛化、是否值得成本。结构共演不保证正收益。

固定评测与预算下，交互量可写为

\[
I=J(M_1,H_1)-J(M_1,H_0)-J(M_0,H_1)+J(M_0,H_0).
\]

它衡量选定四个版本的交互，不是自动的因果证明：训练预算、选择过程、任务分布和随机性也需可比。I>0 不等于持续递归加速；I<0 也不等于所有联合训练路线失败。另用共同目标初态比较旧/新改进者的产出，才能触及“改进能力提高”。

## 5. RSI 闭环资格独立于三层位置

依次核对：AI 产生改动 → 改动确实作用于边界内系统 → 反馈选择/训练 → 改动被继承 → 后继参与后续改进。每条边都应有工件、算法或实际轨迹定位。

自动化、迭代优化、自适应、结构递归、改进能力提高、持续收益是不同命题。主视图既展示已有闭环案例，也展示关键的联合适配证据；卡片明确标记后者尚未实证多轮闭环。评测论文与形式理论保留为横向工具，不充为三种系统的实例。

## 6. ≥27B 是本项目主视图的规模门槛

Model 与混合路线按**实际被训练模型的总参数 ≥27B**筛选；adapter 训练按基座规模计，同时显示训练方式。MoE 同时报总参数与激活量；30B-A3B 不等于 30B dense 的算量或训练成本。多个小模型不可相加；大教师、评审模型与外部 API 不能替代目标模型规模。

同一论文有 8B 与 32B 分支时，在实验层面筛选。未披露或未核准的规模单列。规模通过后还需相关性、贡献、证据与回流判断。小模型记录可保留以追溯机制，但不进入当前主图；这一范围选择不是小模型研究一概无价值的结论。

## 7. A–F 是贡献视角，不是论文填写清单

每项已审研究只提炼 1–3 个主要贡献点；使用 a1–f6 的标签帮助检索。标签是我们的阅读判断，允许重叠。一项工作可以覆盖多个方面，没有“只能占一个点”的定理，也不要求填写所有维度。特别不根据作者身份或机构猜测主观创造力、品味、视野与坚持程度。

卡片先回答：**改了什么 → 为什么有效/何时失效 → 反馈如何回流 → 最值得保留的一点**。来源、实验规模、训练细节与限制放入可展开证据层。

## 8. 全面性应如何检验

主图是已审实例，研究空间表是可能的功能与反馈位置；二者分开。空间表的“本次未确认”可能来自未覆盖、规模不符、证据不够，或真正研究不足，不能宣称全球空白。它不是按论文关键词自动生成的空白，更不是“首次提出”的证明。

普适理论应给出：边界与假设、状态/干预/反馈、可测的机制、失效条件、预算约束、跨任务预测。对象的三分法只能完成其中的表示层。当前没有证据把某个信息论或物理定律直接宣称为所有 RSI 系统的增长定律；精确建模必须进一步辨识反馈质量、分布移动、模型–harness 相容性和资源代价。
